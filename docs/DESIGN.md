# 界面与视觉方案

这份文档记录仓库「看起来是什么样」的决策：配色从哪来、为什么这样排、图怎么出。
改版时按这里的规则改，才不会再出现「换一张更好的立绘反而更难看」的情况。

## 1. 目标与原则

| 原则 | 具体做法 |
| --- | --- |
| **三秒说清是什么** | 第一屏只有四件东西：标题、头图、徽章、一句话。不放目录、不放安装步骤 |
| **先能跑，再讲原理** | `30 秒上手` 紧跟第一屏；原理、取舍、性能排查全部折叠到 `<details>` |
| **截图给语境** | 图里让角色站在「任务栏」上，一眼看出这是桌面宠物，而不是一张立绘贴纸 |
| **克制用色** | 全局只有一个主色（来自角色发色），其余是暖白与灰蓝；不使用多色强调 |
| **信息密度分层** | 能扫的用表格，能背的用代码块，能略过的用折叠 |

## 2. 色彩系统

主色取自立绘本身（`dev/cutout.py` 对角色像素做直方图统计，去掉白与黑后取众数）。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ink` | `#1B2340` | 大标题、正文强调 |
| `--ink-2` | `#3B4767` | 正文 |
| `--ink-3` | `#6C799C` | 次要说明 |
| `--ink-4` | `#98A2BE` | 英文小标、页脚 |
| `--brand` | `#3F4F8F` | 主色（取自发色 `#405090`，压深一档以保证对比度） |
| `--brand-2` | `#5568A8` | 悬停、次级强调 |
| `--line` | `#E2E8F5` | 分隔线、卡片描边 |
| 状态色 | `#5B6FA8` 思考 / `#4A5FBF` 忙碌 / `#3A9A93` 整理 / `#C79A3E` 等待 / `#3F9D6B` 完成 / `#C8594F` 出错 | 只用于六档状态的小圆点 |

- 正文 `#3B4767` 对白底对比度约 **8.9:1**，远超 WCAG AA 的 4.5:1；`--ink-4` 只用于 12px 以上的辅助信息。
- 头图标题用深海军蓝渐变（`#202A4D → #2C3A6B`），不用纯黑——纯黑配圆润字体会显得发死。

## 3. 字体

| 场景 | 字体 | 说明 |
| --- | --- | --- |
| 头图大标题 | **上首软糖体**（`assets/fonts/`） | 圆润的字形和角色的 Q 版比例同源，是整张图「可爱」的来源 |
| 头图正文 / 标签 | Segoe UI → 微软雅黑 | 系统字体，保证任何机器渲染一致 |
| 英文小标 | 同正文，`letter-spacing: .26em` | 拉开字距当装饰用，不靠字号撑气势 |

字号阶梯：`12.5 / 16.5 / 22 / 78`（头图），`12 / 13 / 16 / 20 / 24 / 32`（README 正文交给 GitHub 默认）。

## 4. 间距与形态

- 头图版心 **1440×600**（2.4:1），留白遵循 8 的倍数：左右 92/96，上下 44。
- 卡片圆角 **30px**、卡片内元素圆角 **18px**、标签胶囊全圆角；描边统一 1px `#E6ECF9`。
- 阴影只用一层柔和投影：`0 28px 64px -28px rgba(31,45,92,.34)`，不要多层叠加。

## 5. 仓库信息架构

README 的章节顺序按「读者此刻要什么」排，不按代码结构排：

```
标题 → 头图 → 徽章 → 一句话
30 秒上手          ← 想跑起来的人看到这里就够了
它长什么样          ← 状态条 + 真实运行截图
能做什么            ← 能力总表（扫读）
快捷键与托盘        ← 日常操作速查
跟着 WorkBuddy 动   ← 状态联动表 + 三种接法（折叠）
常驻与自动召唤      ← 回答"为什么它有时不在"
配置 / 常见问题     ← 想改的人、出了问题的人
开发与调试          ← 折叠：调试工具、掩码重算、性能结论
许可与出处
```

折叠（`<details>`）只用于**长尾**：三种接法的细节、自动召唤的原理、四个常见问题、调试与性能排查。
折叠标题本身写成一句人话，读者不展开也知道里面大概有什么。

## 6. 图片规格

| 文件 | 尺寸 | 倍率 | 用途 |
| --- | --- | --- | --- |
| `docs/hero.png` | 1800×750 | 2.05×（对 880 正文宽） | 头图，铺满宽度 |
| `docs/states.png` | 1650×375 | 1.87× | 六档工作状态展示条，圆角卡片 |
| `docs/menu.png` | 924×632 | 1.05× | 真实运行截图（多级菜单） |
| `docs/badges/*.svg` | 矢量 | — | 本地徽章，不依赖 shields.io（国内可访问） |

- 所有截图都烘焙了圆角与 1px 描边，贴在白底上不会出现「渐变被切断」的硬边。
- 立绘从原图**只放大 2 倍**并做 `UnsharpMask`，再在版心内按 ~1.4 倍显示——走的是「先放大再缩回」，而不是直接拉伸。

## 7. 怎么重新生成

```bash
# 0) 一次性的准备：字体 + 立绘抠图
cp "assets/fonts/上首软糖体.ttf" dev/design/font.ttf
python dev/cutout.py                 # 白底立绘 → docs/pet.png（透明），并打印主色

# 1) 渲染三张图（需要 runtime/electron/，见 README 上手第 ① 步）
runtime/electron/electron.exe dev/design/render.cjs --page=hero.html   --out=dev/design/_hero-raw.png   --w=1440 --h=600
runtime/electron/electron.exe dev/design/render.cjs --page=states.html --out=dev/design/_states-raw.png --w=1320 --h=300 --seek=0.45
runtime/electron/electron.exe dev/design/menushot.cjs --out=dev/design/_menu-raw.png   # 需要桥在跑

# 2) 收口：圆角、描边、压缩（见 git log 里 _roundify 的脚本，或用任意图像工具按 §4 的圆角值处理）

# 3) 验收：按 GitHub 正文宽度本地渲染 README，肉眼过一遍
python dev/preview.py
runtime/electron/electron.exe dev/design/readme-shot.cjs
```

> 屏幕分辨率不够时窗口会被系统裁掉，`render.cjs` 会自动按可用区域压 `zoom`，
> 拿到的是「物理像素 ≈ 版心 ×1.25」；若换了 4K 屏，输出会更锐，无需改代码。

`--seek=0.45` 是把六段状态动画定格在 45% 进度，取到有代表性的姿态（问号、气球、沙漏、星星都在这一帧）。
换素材后重新跑一遍即可。
